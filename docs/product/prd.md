# 产品需求文档：Agent Workbench

## 1. 产品概述

Agent Workbench 是一个面向创作者、开发者和运营团队的通用 Agent 控制台。它把不同 Agent 执行器、skills、workflow plugins、MCP 工具、受控 CLI 命令、团队知识库、浏览器自动化、内容资产和任务运行观测统一在一个图形界面中，帮助用户完成自媒体、编码、运营等多步骤任务。

产品核心不是“发明一个新 Agent”，而是成为 Agent 的调度、配置、审批、观察和沉淀中心。每次任务都应沉淀为可追踪的 artifact project：包含输入、上下文引用、工具调用、审批、生成文件、版本和导出包。

## 1.1 优化后的产品主张

结合 Open Design 的调研结论，产品需要补齐三条能力线：

1. **Adapter-first**：Codex、OpenCode、Claude Code、Cursor、GenericAgent 等成熟执行器负责 agent loop，Workbench 负责发现、配置、注入上下文和收集事件。
2. **Workflow Plugin**：在 `SKILL.md` 之上提供机器可读 manifest，声明输入表单、产物类型、MCP/CLI 依赖、权限、pipeline 和预览。
3. **Artifact-first**：自媒体正文、封面、PPT、网页、视频脚本、代码 diff、运营报表都作为可预览、可版本化、可导出的产物管理。

## 2. 目标用户

### 个人创作者

需要完成选题、资料收集、文章撰写、视频脚本、封面生成、发布排期、数据复盘。

### 独立开发者

需要在一个界面中调用编码 Agent、查看文件变更、审批命令、运行测试、整理发布说明。

### 运营团队

需要把重复运营动作流程化，包括监控竞品、整理素材、生成日报、发布内容、同步飞书/Notion/表格。

### Agent Builder

需要调试自定义 Agent、skills、MCP 工具、CLI 工具、模型路由、知识检索和自动化流程。

## 3. 产品目标

| 目标 | 描述 | 衡量指标 |
| --- | --- | --- |
| 降低 Agent 使用门槛 | 把 CLI、配置、权限、工具调用变为可视化操作 | 新用户 10 分钟内完成首个任务 |
| 提升任务可控性 | 所有高风险操作可审批、可追踪、可回放 | 高风险操作 100% 记录审计 |
| 支持跨领域工作 | 编码、内容、运营共用一个工作台 | 单任务可调用 2 个以上 runtime |
| 让能力可沉淀 | Skills、SOP、团队知识、CLI/MCP 连接器、资产可复用 | 每周复用知识条目、skill 或模板次数 |

## 4. 产品定位

### 一句话定位

一个本地优先、可扩展、可审批的多 Agent 工作台。

### 不做什么

- 不直接替代 OpenCode、Codex、Claude Code。
- 不在 MVP 阶段做全云端多租户 SaaS。
- 不默认自动发布到真实账号。
- 不鼓励无审批的高风险自动化。

## 5. 核心使用场景

### 场景 A：自媒体选题到发布

1. 用户选择“自媒体周更流程”。
2. 选题 Agent 抓取热榜、竞品、用户资料。
3. 文案 Agent 生成大纲和正文。
4. 设计 Agent 生成封面或配图。
5. 审核 Agent 检查事实、敏感词、平台格式。
6. 发布 Agent 在获得用户确认后进入发布页面或生成发布包。
7. 数据 Agent 在发布后记录复盘指标。

### 场景 B：编码需求实现

1. 用户选择代码仓库和 coding Agent。
2. 产品经理 Agent 拆需求和验收标准。
3. 开发 Agent 修改文件。
4. 测试 Agent 运行测试或给出验证路线。
5. 用户在文件变更面板中查看 diff 并审批。

### 场景 C：运营日报

1. 定时任务每天拉取数据源。
2. 数据 Agent 清洗并汇总指标。
3. 文案 Agent 生成日报。
4. 用户确认后同步飞书/Notion/邮件。

### 场景 D：创意产物与品牌一致性

1. 用户选择“发布会宣传包”或“产品功能上线包”插件。
2. 系统绑定 `BRAND.md`、`CONTENT.md`、平台规则和历史案例。
3. 设计/内容 Agent 生成 landing page、社媒海报、PPT、短视频脚本。
4. 用户在 Artifact Studio 中预览、评论、二次编辑。
5. 审核通过后导出 HTML/PDF/PPTX/ZIP 或发布包。

## 6. 信息架构

| 一级模块 | 二级功能 |
| --- | --- |
| 工作台 | 总览、运行中任务、任务详情、审批队列、系统状态 |
| Agents | 单 Agent、Agent Team、角色提示词、模型、运行器、关联 skills |
| Skills | 已安装、市场、权限、依赖、更新、测试 |
| 知识库 | 团队资料、项目 SOP、决策记录、账号规则、检索、引用、版本 |
| 连接器 | MCP servers、CLI commands、环境变量、权限、健康检查、审计 |
| 插件 | Workflow plugin、输入 schema、pipeline、权限、预览、安装与自检 |
| 工作流 | 模板、编排、定时任务、触发器、人工审批节点 |
| Creative Studio | 文章、落地页、PPT、图片、视频脚本、品牌与内容契约 |
| 资产 | 文档、图片、视频、网页采集、生成物、发布包、代码 diff |
| 运行观测 | token、耗时、工具调用、错误、成本、模型表现 |
| 设置 | 模型提供商、账号授权、安全策略、数据目录 |

## 7. 功能需求

### 7.1 任务中心

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| T-01 | 创建任务，选择 Agent 或 Agent Team | P0 |
| T-02 | 展示流式输出、工具调用、文件变更 | P0 |
| T-03 | 支持暂停、停止、继续任务 | P0 |
| T-04 | 支持任务状态：排队、运行、等待审批、完成、失败、取消 | P0 |
| T-05 | 支持任务回放和日志导出 | P1 |

### 7.2 Agent 管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| A-01 | 创建/编辑 Agent：名称、角色、系统提示词、默认模型、runtime | P0 |
| A-02 | Agent 绑定 skills、MCP 工具、CLI 命令和知识库范围 | P0 |
| A-03 | 创建 Agent Team，支持串行流程 | P0 |
| A-04 | 支持并行、审核、Router 工作流 | P1 |
| A-05 | 支持导入/导出 Agent 配置 | P1 |

### 7.3 Skill 管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S-01 | 扫描本地 skill 包并展示元数据 | P0 |
| S-02 | 启用、禁用、卸载 skill | P0 |
| S-03 | 展示 skill 权限声明和风险等级 | P0 |
| S-04 | 运行 skill 自检和依赖检查 | P1 |
| S-05 | 从 GitHub/SkillHub/本地 zip 安装 | P1 |

### 7.3.1 Workflow Plugin 管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| W-01 | 支持安装本地 workflow plugin：`SKILL.md` + `plugin.json` + assets | P0 |
| W-02 | Plugin 可声明输入 schema、默认 Agent Team、产物类型和 pipeline stage | P0 |
| W-03 | Plugin 可声明依赖的 skills、MCP tools、CLI commands、知识库范围 | P0 |
| W-04 | Plugin 启动前展示 capability gate，用户确认高风险能力 | P0 |
| W-05 | 支持 plugin 自检、预览样例、版本和来源管理 | P1 |

### 7.4 Runtime Adapter

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| R-01 | 接入 OpenCode 或 Codex 作为 coding runtime | P0 |
| R-02 | 接入 GenericAgent-style worker 作为运营/浏览器 runtime | P0 |
| R-03 | 统一事件模型：message、tool_call、approval、artifact、metric | P0 |
| R-04 | 支持 HTTP/SSE worker 协议 | P0 |
| R-05 | 支持 CLI adapter 作为兼容路径 | P1 |

### 7.5 团队知识库管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| K-01 | 创建团队知识库和项目知识库，支持按项目、频道、标签分类 | P0 |
| K-02 | 支持导入 Markdown、PDF、网页、会议纪要、代码文档、表格摘要 | P0 |
| K-03 | 每条知识保留来源、作者、更新时间、可见范围和引用链接 | P0 |
| K-04 | Agent 运行时可按绑定范围检索知识，并在回答中返回引用 | P0 |
| K-05 | 支持 SOP、账号规则、品牌语气、发布规范等结构化知识模板 | P1 |
| K-06 | 支持知识版本、过期提醒、冲突检测和人工审核 | P1 |

### 7.6 MCP 与 CLI 连接器

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| C-01 | 项目级注册 MCP server：名称、transport、命令/URL、环境变量、启用状态 | P0 |
| C-02 | 项目级注册 CLI command：命令模板、参数 schema、工作目录、权限等级 | P0 |
| C-03 | Agent 可绑定特定 MCP tools 或 CLI commands，而不是默认拥有全部能力 | P0 |
| C-04 | MCP/CLI 执行统一进入工具调用流、权限审批、审计日志和运行指标 | P0 |
| C-05 | 支持连接器健康检查、测试调用、版本信息和失败诊断 | P1 |
| C-06 | 支持从项目模板导入常用 MCP/CLI 配置 | P1 |

### 7.7 权限与审批

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| P-01 | 命令执行、文件写入、浏览器发布、外部 API 调用需按策略审批 | P0 |
| P-02 | 审批弹窗展示动作、参数、风险、来源 Agent | P0 |
| P-03 | 支持本次允许、会话允许、拒绝、修改参数后允许 | P0 |
| P-04 | 所有审批和执行结果写入审计日志 | P0 |
| P-05 | 支持策略模板：保守、协作、自动化 | P1 |

### 7.8 资产与发布包

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M-01 | 自动收集任务生成的文档、图片、视频、代码 diff | P1 |
| M-02 | 支持生成“发布包”：正文、标题、封面、标签、平台格式 | P1 |
| M-03 | 支持资产预览和版本记录 | P1 |
| M-04 | 支持 Artifact Studio：HTML/PDF/PPT/图片/视频脚本/diff 统一预览 | P1 |
| M-05 | 支持 artifact manifest，记录来源 Agent、知识引用、plugin、父版本 | P1 |

### 7.9 品牌与内容契约

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| B-01 | 项目可维护 `BRAND.md`：视觉、语气、组件、反模式 | P1 |
| B-02 | 项目可维护 `CONTENT.md`：账号定位、栏目、平台格式、禁用表达 | P1 |
| B-03 | Agent 运行时自动注入绑定契约，并在产物中记录契约版本 | P1 |
| B-04 | 支持从历史产物或知识库生成契约草稿 | P2 |

## 8. 非功能需求

| 类型 | 要求 |
| --- | --- |
| 安全 | 默认本地运行，高风险动作需审批，secret 不进入 prompt 明文 |
| 可观测性 | 每次运行记录模型、token、耗时、工具调用、错误 |
| 可扩展性 | runtime adapter、skill、MCP、CLI、knowledge source、workflow 均可插件化 |
| 可恢复性 | 任务失败后可查看上下文、重试、从检查点继续 |
| 易用性 | 新用户不需要理解 CLI 参数即可启动任务 |

## 9. MVP 范围

### 必须交付

- 本地 Web 或 Electron 控制台
- 任务中心
- Agent/Team 管理
- Skill 管理
- 团队知识库管理
- MCP/CLI 连接器管理
- Workflow Plugin 管理
- OpenCode/Codex adapter 二选一
- GenericAgent-style worker adapter
- 权限审批
- 运行日志
- 自媒体工作流模板
- Artifact Studio 基础预览

### 暂不交付

- 公开云端市场
- 团队多租户 RBAC
- 移动端
- 完整计费系统
- 全自动跨平台发布

## 10. 成功标准

1. 用户能通过图形界面创建一个自媒体内容任务，并得到文章草稿和发布包。
2. 用户能通过图形界面启动编码任务，并看到工具调用和文件 diff。
3. 用户能安装/启用/禁用一个 skill。
4. 用户能创建一个项目知识库，导入 SOP，并让 Agent 在任务中引用。
5. 用户能注册一个 MCP server 和一个 CLI command，并绑定给指定 Agent。
6. 用户能对高风险命令进行审批。
7. 系统能展示任务耗时、token、工具调用次数和失败原因。
8. 用户能通过 workflow plugin 启动自媒体周更流程，并导出发布包。
9. 用户能在 Artifact Studio 中查看产物、知识引用和版本来源。
