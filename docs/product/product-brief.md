# 产品概览

Agent Workbench 是一个本地优先的通用 Agent 工作台，面向需要同时管理内容生产、编码实现、运营分析和交付资产的个人或小团队。

## 产品定位

提供一个可视化控制台，把 Agent、Skills、Workflow Plugins、团队知识库、MCP / CLI 工具、审批和产物管理放在同一个工作流中。用户不需要先理解底层执行器，只需要从任务目标出发，逐步配置协作角色、工具权限和交付物。

## 目标用户

- 自媒体运营者：需要从选题、写作、封面、发布包到复盘的稳定流程。
- 开发者：需要把编码任务、CLI、代码产物和变更记录纳入可追踪流程。
- 运营或产品团队：需要将日常分析、资料整理、内容交付和审批动作标准化。
- Agent 构建者：需要一个本地优先的控制台来验证多 Agent 编排和工具接入。

## 核心对象

- Task：一次可追踪的工作请求。
- Agent：具备 runtime、模型、技能、知识范围和权限策略的执行角色。
- Agent Team：按顺序或工作流组织的一组 Agent。
- Skill：可复用能力说明和执行约束。
- Workflow Plugin：带 pipeline、capabilities、MCP / CLI 声明的场景化插件。
- Knowledge Item：团队或项目知识条目。
- Connector：MCP server 或 CLI command 的受控入口。
- Approval：高风险动作的人工确认记录。
- Artifact：任务或工作流产生的交付物与版本。

## 产品原则

- 本地优先：默认把数据和执行控制留在用户机器上。
- 审批优先：中高风险工具调用必须可见、可拒绝、可审计。
- 产物优先：每次运行都尽量沉淀为可查看、可导出、可版本化的资产。
- 图形优先：常规操作通过页面完成，高级用户可导入导出 YAML 或 JSON。
- 可渐进增强：静态模式能演示和轻量使用，API 模式提供真实本机能力。
